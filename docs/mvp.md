# Первая рабочая версия UniLoad

Основа — ТЗ из ЛР № 2, прототип из ЛР № 3 и backlog из ЛР № 4. Страница предыдущих работ сохраняется в `tempPage`.

Основной сценарий: главная → список → создание задания → сохранение → выбор ближайшего срока → отметка выполнения → повторное открытие списка.

В первую версию входят FR-01–FR-12: создание, изменение, подтверждаемое удаление, срочность, совместные фильтры, сортировка, выполнение, общие счётчики и localStorage. Нужны пустой список, отсутствие совпадений, ошибки полей и ошибки чтения/записи. На 360, 768 и 1200 px основные действия должны оставаться доступны.

Аккаунты, сервер, синхронизация, календарь и уведомления в этот объём не входят. Развёрнутая программа испытаний относится к ЛР № 7. До сдачи ЛР № 6 проверяются основной сценарий, сборка и перечисленные состояния.

## Последовательность реализации

Каждая следующая задача начинается после проверки предыдущего этапа. Для работы с ИИ сформулированы следующие отдельные задачи.

1. **Основа приложения — FE-003, FE-004.** React, Vite, JavaScript и CSS; сохранить старую страницу. Результат: запускаемая оболочка и успешная сборка. Сторонние UI-библиотеки и сервер не нужны.
2. **Модель и хранение — FE-006–FE-008, FE-014.** Шесть полей Task из ТЗ, проверка данных, расчёт календарной срочности, чтение и запись JSON. Проверить границы дат, повреждённый JSON и отказ записи. Не удалять данные автоматически.
3. **Форма — FE-009–FE-012.** Общая форма создания и редактирования, ошибки рядом с полями, отмена без изменений. При редактировании сохранять id, createdAt и completed. Проверить сохранение и повторное открытие.
4. **Список и действия — FE-013, FE-015, FE-016.** Карточки из общего массива, удаление с подтверждением и выполнение в обе стороны. Проверить отмену удаления и общие счётчики.
5. **Фильтры и состояния — FE-017–FE-020.** Совместная фильтрация, стабильная сортировка, пустые результаты, повтор сохранения и явный сброс повреждённых данных. Проверить, что фильтры не меняют исходный массив.
6. **Интерфейс — FE-005, FE-021, FE-022.** Повторно используемые элементы, адаптивность, подписи полей, управление клавиатурой и возврат фокуса. Проверить узкий экран, длинный текст и основные переходы.

Для каждой задачи сохраняется отдельный логический коммит после проверки. Даты коммитов соответствуют фактическому выполнению работы.

## Результат ЛР № 6

Реализованы FR-01–FR-12. Главная страница показывает ближайшие активные задания; список, форма и сводка используют одни данные. Исходники разделены на компоненты, страницы, функции модели и слой хранения. Статическая страница ЛР № 4–5 сохранена без изменений. Существенных противоречий между ТЗ и прототипом при выборе этого объёма не обнаружено.

Проверки выполнены 22 октября 2026 года в Microsoft Edge 155.0.4283.62:

| Проверка | Результат |
| --- | --- |
| Запуск dev-сервера и production-сборка | Приложение открывается, build завершается |
| Создание, изменение, отмена формы, повторное открытие | Данные сохраняются; отмена не меняет список; id и createdAt при изменении сохраняются |
| Пустые и пробельные поля, неверные даты, текст с HTML-тегами | Ошибки полей; введённый текст не выполняется как HTML |
| Выполнение в обе стороны, сводка, удаление и отмена удаления | Список и общие счётчики обновляются; удаление требует подтверждения |
| Совместные фильтры, равные сроки и обратная сортировка | Отбор корректен, порядок при равных сроках стабилен |
| Границы срочности и выполненные задания | Сегодня и ближайшие два дня различаются; выполненные не просрочены |
| Пустой список и отсутствие совпадений | Разные сообщения с действием для продолжения |
| Ошибки чтения, повреждённый JSON, отказ записи | Текущий список доступен; есть повтор; повреждённые данные заменяются только с подтверждением |
| Ширины 320–1440 px, длинные строки и шрифт 200% | Горизонтального переполнения не обнаружено |
| Клавиатура, ошибки полей, диалог и ссылка пропуска | Элементы подписаны; фокус доступен и возвращается после отмены |

Основной сценарий дополнительно пройден на собранных файлах через `vite preview`: пустой список → создание → редактирование → выполнение → фильтр → повторное открытие вкладки → удаление. Критических ошибок и ошибок консоли при этой проверке не обнаружено. Отсутствующая иконка вкладки давала запрос 404; иконка добавлена, проверка повторена.

## Использование ИИ и дальнейшая работа

Codex использовался для реализации компонентов, функций модели и хранения, CSS, анализа ошибок и выполнения проверок. Работа разделена на задачи из плана выше; изменения фиксировались после проверки соответствующего этапа. Отдельно проверены предложенные обработка отказа записи и защита повреждённого JSON: сообщение об успехе не должно скрывать несохранённые данные.

Локальные проверки подтверждают готовность демонстрационного сценария. FE-023 и FE-024 пока не закрыты: постоянный набор автоматизированных тестов и проверка Chrome, Firefox и Safari ещё не выполнены. Данные не синхронизируются между вкладками и устройствами; backend, аккаунты и production-развёртывание в этот этап не входят.
