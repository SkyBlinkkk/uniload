# Тестирование UniLoad

В ЛР № 7 проверяются три требования из ТЗ ЛР № 2. Примеры MenuFlow использованы как образец настройки Vitest и проверок через пользовательские действия; предметная область и данные остаются из UniLoad.

| Требование | Что проверяем | Тесты |
| --- | --- | --- |
| FR-02 | Пустые и пробельные поля, существование даты, исправление ошибок без сохранения неверных данных | T01–T08 |
| FR-08 | Дисциплина и выполнение применяются одновременно; снятие фильтров возвращает список | T09–T10 |
| FR-10 | Выполнение меняется в обе стороны, общие счётчики не зависят от фильтров | T11–T12, также T09 |

Проверки записи и повторного чтения данных в T08, T11 и T12 дополнительно затрагивают FR-11. Пустая выдача в T10 и T12 затрагивает FR-12. Полное покрытие этих требований здесь не заявляется.

## Условия и ожидаемые результаты

Тесты изолированы: перед каждым запуском сценария очищаются localStorage среды jsdom и адрес страницы, после него удаляется смонтированный интерфейс. Используются три вымышленных задания: активное и выполненное по математике, активное по веб-разработке. Начальное состояние задаётся в самом тесте. Сервер и пользовательские данные не требуются.

| ID | Действие или входные данные | Ожидаемый результат |
| --- | --- | --- |
| T01 | Отправить пустую форму | Ошибки всех трёх полей; фокус на названии; обработчик сохранения не вызван |
| T02 | Ввести пробелы в название и дисциплину, корректную дату | Два текстовых поля невалидны, дата валидна; сохранения нет |
| T03 | После пустой отправки заполнить форму с датой 2020-01-15 | Ошибки исчезают; корректные значения передаются на сохранение один раз, прошедшая дата разрешена |
| T04 | Дата 2024-02-29 | Високосный день принят без ошибки |
| T05 | Дата 2025-02-29 | Несуществующая дата отклонена |
| T06 | Дата 2026-04-31 | День за границей месяца отклонён |
| T07 | Дата 0000-01-01 | Нулевой год отклонён |
| T08 | В App отправить пустую форму при уже сохранённых заданиях | Форма остаётся открытой с ошибками; запись localStorage не меняется; сообщения о добавлении нет |
| T09 | Математика + «Активные», затем «Выполненные» | Виден только соответствующий элемент математики; веб-разработка скрыта; общие числа 2/1 и сохранённый список не меняются |
| T10 | Веб-разработка + «Выполненные», затем сброс | Сначала «Ничего не найдено» и 0 из 3; сброс возвращает три задания без изменения данных |
| T11 | Из двух активных завершить одно, повторно смонтировать App, снять отметку и открыть App ещё раз | Числа 2/0 → 1/1 → 2/0; оба сохранённых состояния читаются повторно; остальные поля и задания не меняются |
| T12 | В фильтре активной математики завершить последнее видимое задание | Оно исчезает из выдачи, но остаётся в хранилище; числа 1/2; фокус переходит к добавлению; в выполненных задача видна с отметкой |

T01–T03 — компонентные проверки, T04–T07 — модульные. T08–T12 рендерят App целиком и проверяют взаимодействие формы, фильтров, карточек, сводки и localStorage. Несуществующие даты проверяются на уровне validateForm: поле HTML date само может не принять такую строку.

## Запуск

Нужны Node.js 22.12+ и pnpm 11.25.0. Из корня репозитория:

```sh
pnpm install --frozen-lockfile
pnpm test:run
pnpm build
```

`pnpm test` — режим наблюдения, `pnpm test:run --reporter=verbose` — подробный вывод. В случае ошибки сначала сопоставьте упавший expect с требованием и фактическим DOM. Ожидание нельзя менять только ради успешного запуска.

## Результат 25 октября 2026 года

Windows, Node.js 24.22.1, pnpm 11.25.0; Vitest 5.0.5, jsdom 30.1.3. Все 12 тестов в трёх файлах проходят. Исходная сборка до изменений и итоговая production-сборка успешны.

При первом запуске три компонентных теста не находили поле по точному тексту label: в подписи также есть звёздочка обязательности. Для текстовых полей использован поиск по роли textbox и доступному имени; для даты — по подписи без требования точного совпадения. Это исправление тестовых запросов, поведение формы не менялось. После исправления прошли семь проверок валидации, затем добавлены и успешно запущены пять интеграционных проверок.

Ошибок приложения в выбранных сценариях не выявлено, производственный код не менялся. Отдельной команды lint в проекте нет. Проверка внешнего вида, ошибок хранилища, удаления, редактирования и всех браузеров этим набором не покрывается. FE-023 и FE-024 остаются открыты до проверки остальных критериев этих задач.

Codex использовался для подготовки тестов, настройки среды, анализа первых ошибок запуска и оформления результатов. Условия проверок взяты из ТЗ и сопоставлены с текущим интерфейсом UniLoad.

Техническая справка: [Vitest](https://vitest.dev/guide/), [React Testing Library](https://testing-library.com/docs/react-testing-library/setup/).
